Assignment 1 Proposal

My proposed creative tool for Assignment 1 is an interactive web-based expressive experience centred around a calm moving line that responds to emotional input. As users add feelings or thoughts, the line gradually changes in behaviour, becoming more unstable, layered, and disrupted over time. The project explores how emotion can be translated into abstract visual form rather than being represented literally.

Purpose

The purpose of this creative tool is to give users a simple but expressive way to externalise emotion through interaction. My current concept is an interactive web-based experience built around a calm moving line that reacts to emotional input. Users may be invited to enter a feeling, briefly explain what may have caused it, and adjust a general intensity slider from 1 to 10. Rather than turning these responses into direct storytelling or fixed categories, the tool translates emotional input into visual behaviour. As more responses are added, the line may begin to shift, branch, distort, or lose stability, allowing emotion to be represented through movement and change rather than literal description. I am interested in exploring how a minimal visual system can still communicate something deeply personal and layered. At this stage, the project remains intentionally open, as the exact form of interaction and visual response may continue to evolve. However, the overall aim is to create a reflective space where emotion can be experienced as rhythm, tension, build-up, and disruption in an abstract but engaging way.

Value

The value of this creative tool lies in its ability to make something internal feel visible, immediate, and interactive. Emotions are often difficult to explain clearly because they can be layered, unstable, and deeply personal. By using a responsive line as the main visual language, the project offers users a way to express what they are feeling without relying only on words. This gives the tool both emotional and creative value, as it encourages interpretation rather than forcing users into overly rigid forms of self-description. I think the abstraction is important, because it allows the experience to feel more open and personal. Instead of trying to define emotion too literally, the project suggests it through motion, instability, pacing, and visual disruption. There is also value in how the interaction may create a sense of accumulation over time, where each contribution leaves a trace and gradually shifts the overall system. The intensity slider adds another layer of flexibility, allowing users to define emotional intensity in their own way. Overall, the project aims to create an experience that feels thoughtful, expressive, and open to multiple interpretations.

Assignment 2

Project Overview

Pulse Diary is an interactive web-based prototype that explores how daily emotions can be translated into a visual pulse. Building on the initial concept developed in Assignment 1, this stage focuses on turning that idea into a functional mock-up that users can interact with and respond to through peer testing. The project invites users to record how they feel on a given day using emotional selections and adjustable input values, which then generate a pulse-based visual outcome. Rather than treating emotion as something fixed or easily categorised, the prototype explores it as layered, shifting, and personal. This page documents the development of the project so far, including its conceptual direction, technical implementation, prototype outcome, peer testing insights, and the next steps for further refinement.

Conceptual Response

This project explores how emotion can be translated into a visual and interactive form through a browser-based experience. The chosen creative context is a personal reflective tool, where users are invited to record how they feel and see that emotional state represented through a pulse visualisation. Rather than presenting emotion as fixed or easily measurable, the project approaches it as something layered, unstable, and deeply personal. The main interaction design principle explored in this work is feedback, as the user's emotional selections and slider inputs directly shape the generated pulse. This principle is applied in a more expressive way by using the pulse not as literal health data, but as an abstract emotional response. The project aims to create a space that feels reflective rather than clinical, allowing users to see their feelings translated into movement, rhythm, and visual change.

Prototype Overview

The current prototype presents the project as an interactive emotional check-in tool centred around a pulse-based visual response. Users are invited to record how they feel on a chosen day by selecting an emotion and adjusting a range of input values that influence the resulting pulse. At this stage, the prototype focuses on the core interaction flow rather than a fully expanded system, allowing users to experience the relationship between emotional input and visual output. The mock-up already establishes the overall layout, basic interaction logic, and pulse generation concept, while also giving a sense of how the final experience may develop over time through repeated entries. Although some areas remain incomplete or open to refinement, the prototype functions as a working demonstration of the project's main idea and formed the basis for peer user testing and feedback.

Technical Approach

The prototype is structured across three main files: index.html, style.css, and main.js, with each file handling a different part of the experience. In index.html, I built the core interface structure of the project, including the sidebar calendar, selected day display, top navigation bar, daily and weekly view containers, the SVG heartbeat display, and the slide-in emotion entry modal. This file establishes the full interaction layout before any styling or behaviour is added, making the project readable as a complete system at the markup level. The HTML also uses clear class naming and data attributes, such as data-view and data-emotion, so that JavaScript can target interactive elements more cleanly later on.

In style.css, I focused on translating the concept into a visually cohesive interface. The styling uses CSS custom properties to manage the full colour system, spacing, shadows, radii, and theme values, which makes the design easier to maintain and switch between dark and light mode. The layout is built with CSS Grid and Flexbox, allowing the interface to separate into a sidebar and main monitor area on desktop while still collapsing responsively on smaller screens. I also used layered gradients, blur, glow, and shadow effects to give the interface a polished, slightly atmospheric quality rather than a plain dashboard look. The heartbeat monitor itself is styled as a large display panel with a grid background, animated glow layer, and an SVG line that feels active once a pulse is generated.

The main interaction logic is handled in main.js. I used a DOMContentLoaded wrapper so all interface elements are available before any logic runs, then selected the main buttons, sliders, modal controls, calendar days, and SVG pulse elements through querySelector and getElementById. From there, I created a central appState object to store the current view, theme, selected emotion, selected date, whether a pulse has been generated yet, the slider values, and the user's note. This allows the prototype to manage the interface as a state-driven system rather than a set of disconnected button clicks.

One of the most important technical parts of the project is the way the pulse line is generated. Rather than swapping between preset images, the prototype builds the SVG path dynamically in JavaScript using the buildPulsePath() function. This function reads the current emotional input values and translates them into visual properties such as amplitude, jitter, recovery, and uplift. Different emotions then modify those behaviours further. For example, calm reduces amplitude and jitter, angry increases them, and anxious produces a more unstable result. The code then generates a full SVG path string point by point, creating either smoother curves or sharper angular changes depending on the emotional state selected. This means the pulse is not decorative only, but computationally shaped by the user's input.

The colour system is also handled programmatically. A palette object maps emotions to different colours, and the applyLineColor() function changes the stroke of the heartbeat line after a pulse is generated. For the mixed state, I added a function that creates an SVG linear gradient inside a <defs> element if it does not already exist, then applies that gradient to the pulse stroke. This allowed the pulse colour to act as another layer of emotional feedback instead of relying on shape alone.

I also used JavaScript to manage the broader flow of the interface. Functions such as setView(), toggleTheme(), openModal(), closeModal(), setEmotion(), and selectCalendarDay() update the visible state of the prototype and keep the layout interactive. Event listeners are attached to the view buttons, theme toggle, modal controls, emotion chips, calendar buttons, sliders, note field, and keyboard input. This means the interface responds in real time as users move sliders, switch views, or update text, especially once the pulse has already been generated. The monitor text is also updated through updateMonitorText() so the written feedback below the pulse changes alongside the visual response.

Overall, the technical approach focuses on turning emotional input into a responsive visual system through a combination of semantic HTML structure, atmosphere-driven CSS styling, and state-based JavaScript logic. The prototype is still limited in scope, particularly because the weekly view is currently a preview rather than a fully data-driven history system, but the current implementation already demonstrates the core mechanism of the project: user emotion is entered through interface controls and translated into a changing pulse that acts as a form of mediated visual feedback.
